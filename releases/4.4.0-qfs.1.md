First release of QFastServer for QGIS Server 4.4.0: the 15 patches of the 3.44 series, ported to QGIS 4.4
and Qt 6.

```bash
docker pull ghcr.io/envirosolutionspl/qfastserver:4.4.0-qfs.1
```

Use the image exactly as `qgis/qgis-server:4.4.0-resolute`: same ports, volumes and environment variables.
Without the options `QFASTSERVER_WORKERS` and `QFASTSERVER_GZIP` the container is started by the unchanged
start script of the official image.

## Verification

- Responses compared with the official image `qgis/qgis-server:4.4.0-resolute`, 59 request types, two passes:
  57 of 59 identical in each pass. The two others (8 bits PNG, PDF) also differ between two processes of the
  official image itself, which compared with itself gave 57 of 59 as well.
- The libraries and the FastCGI binary of the image link the same shared libraries as the official ones.
- Upstream tests on the patched build, at the tag `final-4_4_0`: server (WMS, WFS, WFS-T, GetPrint,
  GetLegendGraphic, GetFeatureInfo, access control, configuration cache), DXF export, rasters, GDAL provider,
  projects, vector tiles: 44 of 44. With PostgreSQL: PyQgsProject, PyQgsProjectStoragePostgres,
  PyQgsServerWMSGetFeatureInfoPG, PyQgsServerAccessControlWMSGetMapPG and
  PyQgsServerAccessControlWMSGetPrintPG passed; PyQgsPostgresProvider 314 of 315, the failing case
  (`testEwkt`) fails in the same way on the unpatched build with the same test database.
- 85 raster renderings (reprojected and not) give the same pixels as the unpatched build.
- Start of the image: with the defaults, one process as the official image; with `QFASTSERVER_WORKERS=3`
  three processes; together with `NGINX_CORS_ALLOW_ORIGIN` of the official image; with
  `QFASTSERVER_GZIP=true` the XML responses are compressed.

## Changes since the 3.44 series

- The same 15 patches, ported to QGIS 4.4. The patch for the DXF export was rewritten: QGIS 4.4 writes DXF
  files through a text codec, so the group codes are now kept already encoded.
- Patch 0013 (GML of WFS) only acts with Qt 5. With Qt 6 it changes nothing; QGIS 4.4 writes GML as fast as
  3.44 with this patch.
- The image is built with Qt 6 and the options of the upstream Debian packaging of 4.4 (PDF4Qt, SFCGAL,
  GeographicLib, TBB).

See the [README](https://github.com/envirosolutionspl/QFastServer#options-of-the-image) for the options and
[UPSTREAM.md](https://github.com/envirosolutionspl/QFastServer/blob/main/UPSTREAM.md) for the patches.

## Known differences from upstream

- PNG files of vector maps are smaller; PNG files of pure imagery are about 20% larger (rows are written
  without the filter search).
- The image is built with the options of the upstream Debian packaging, without the desktop application and
  the GRASS plugins, which the official server image does not contain either. The landing page web
  application of the official image is kept.
- The command of the image is another script, which runs the one of the official image.

## Not verified

- Python server plugins (for example `lizmap_server`) with this image.
- WFS transactions, GetPrint with an atlas, GeoPDF.
- The start of a project of 200 layers (measured for the 3.44 series only).
- The share of each patch in the gains on 4.4.
