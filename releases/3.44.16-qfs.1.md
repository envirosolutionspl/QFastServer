QFastServer for QGIS Server 3.44.16: the 15 patches of the 3.44 series on the new upstream release.

```bash
docker pull ghcr.io/envirosolutionspl/qfastserver:3.44.16-qfs.1
```

Use the image exactly as `qgis/qgis-server:3.44.16-noble`: same ports, volumes and environment variables.
Without the options `QFASTSERVER_WORKERS` and `QFASTSERVER_GZIP` the container is started by the unchanged
start script of the official image.

## Verification

- Responses compared with the official image `qgis/qgis-server:3.44.16-noble`, 59 request types, two passes:
  53 of 59 identical in each pass. The six others (GetContext, 8 bits PNG, a cascaded WMS layer as PNG and as
  JPEG, PDF, DescribeFeatureType) also differ between two processes of the official image itself: compared
  with itself it gave 54 and 55 of 59, and twelve repetitions of the cascaded PNG and of DescribeFeatureType
  give several answers on both images, the most frequent one being the same.
- The libraries and the FastCGI binary of the image link the same shared libraries as the official ones.
- Upstream tests on the patched build at the tag `final-3_44_16`: server (WMS, WFS, WFS-T, GetPrint,
  GetLegendGraphic, GetFeatureInfo, access control, configuration cache), DXF export, rasters, GDAL provider,
  projects, vector tiles: 41 of 41 (two of them only when run alone; with 8 tests in parallel one ran out of
  time and one was aborted). With PostgreSQL: PyQgsPostgresProvider, PyQgsProject,
  PyQgsProjectStoragePostgres, PyQgsServerAccessControlWMSGetMapPG, PyQgsServerAccessControlWMSGetPrintPG,
  PyQgsServerWMSGetFeatureInfoPG: 6 of 6.
- The patches are the same as in 3.44.15-qfs.2, only rebased on the new tag; the series still applies to
  `final-3_44_15` as well.
- Start of the image: with the defaults, one process as the official image; with `QFASTSERVER_WORKERS=3`
  three processes.

## Changes since the previous release

- Built on QGIS Server 3.44.16 instead of 3.44.15. The patches are unchanged.
- The build options which differ between the upstream lines moved from the Dockerfile to
  `versions/<version>.env`; for 3.44 they are the same options, and the image links the same libraries as the
  official one.

See the [README](https://github.com/envirosolutionspl/QFastServer#options-of-the-image) for the options and
[UPSTREAM.md](https://github.com/envirosolutionspl/QFastServer/blob/main/UPSTREAM.md) for the patches.

## Known differences from upstream

- PNG files of vector maps are smaller; PNG files of pure imagery are about 20% larger (rows are written
  without the filter search).
- The image is built with the options of the upstream Debian packaging, without the desktop application and
  the GRASS plugins, which the official server image does not contain either.
- The command of the image is another script, which runs the one of the official image.

## Not verified

- Python server plugins (for example `lizmap_server`) with this image.
- WFS transactions, GetPrint with an atlas, GeoPDF.
- The memory used by several processes with large projects.
